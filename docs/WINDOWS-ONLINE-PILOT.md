# Separate online Windows POS — read-only pilot QA

**This is an installable Windows x64 Electron `.exe`, not a browser/PWA shortcut and not the offline till.** It opens the existing online POS at **https://pos.mansutrendzgh.com/** in its own native window. The web POS remains available and unchanged. This first installer is visibly labelled **ONLINE · READ-ONLY PILOT · NO CHECKOUT**. It is a **test build, not a selling release**: the deployed pilot's server-side Woo/checkout gates remain OFF, and the Windows app independently rejects sale, stock, cash, Wholesale-price and staff-write requests (except sign-in, sign-out and password change). Do not accept payment or release goods from a reference cart.

## How it works

- At launch, and every 15 seconds while running, the app fetches `/api/health` from the **exact pinned HTTPS POS host** and requires `ok: true`, `mode: live`, `liveReadOnly: true`. It refuses a redirected, HTML, unhealthy, writable or unreachable service. The window displays the remote web POS; staff sign in with their existing **POS** account. Current catalogue/stock and history come from the POS service, which reads WooCommerce. There are no Woo credentials in the Windows installer.
- The renderer has no Node/IPC bridge, SQLite database, local POS server, Woo reservation, offline stock allocation, sale commit, sync client or update feed. Its session is memory-only with HTTP cache off and `/sw.js` blocked. No service worker stores an offline app. On interruption, the app hides the old window and exits with a connection warning; reopen only when HTTPS is healthy. A cart or held cart is **not** a paid sale and is not carried across app restarts.
- A failed or lost checkout response in a **future, separately approved selling build** could mean the online server did process the request. It must be reconciled in server Sales/Woo before retrying with a new key. There is **no offline receipt or later-sync queue**. This pilot build cannot reach a checkout endpoint at all, even if someone changes the pilot's web setting.
- The standard web register supports keyboard-wedge USB/Bluetooth barcode scanners (`F2` to scan). The web receipt uses Windows' normal print dialog and installed printer driver **only after an online, server-confirmed payment**; the pilot cannot make a paid receipt. This build has no direct ESC/POS/USB drawer command, no background printing and no receipt offline. The separate [hardware check](HARDWARE-TEST.md) was reported successful, but physical printer and real-sale acceptance for this build are still outstanding. The app blocks downloads (including report CSV export), external navigation and unapproved permissions. Product pictures load only from the POS host or the store's HTTPS WordPress uploads; unsupported CDN photos fall back to placeholders.

## Obtain and check the QA installer

The `npm run dist:online:win` script builds a **separately identified** NSIS x64 Windows installer with `--publish never`. Windows CI runs its isolation tests, boots the packaged Electron window **without contacting the real pilot**, inspects the ASAR, confirms the installer is unsigned and records its SHA-256. Only an explicitly tagged `[online-qa]` push attaches the installer as a short-lived GitHub Actions artifact; normal CI and this script do not create a GitHub Release. There is no auto-update or public distribution. The earlier offline till and SAMPLE practice installer are different applications and are **not** the online POS.

1. On a Windows x64 **test** PC, open this branch's successful **Online pilot QA package** Actions run on GitHub, download its `online-pos-READ-ONLY-PILOT-Windows-x64-…` artifact and extract it. Read `READ-ME-ONLINE-PILOT.md` inside the zip. Do not use an EXE from a different run or a website other than the approved pilot.
2. In PowerShell, compare `Get-FileHash .\Mansu-POS-ONLINE-READ-ONLY-PILOT-*-Windows-Setup.exe -Algorithm SHA256` with the included `SHA256.txt`. Check the filename/label says **READ-ONLY PILOT**. If they differ, stop. This QA installer is **unsigned**; Windows may warn or block it. Do not globally disable Windows protection or TLS verification. Production distribution requires a reviewed, signed build and separate approval for a public GitHub Release.
3. Install per-user. Its `Mansu POS Online (READ ONLY PILOT)` Start/desktop shortcut is independent of the web-installed PWA, the offline draft and the practice/hardware apps. Sign in with a named POS staff account **only after checking the HTTPS pilot and its no-checkout banner**. Do not enter WordPress, WooCommerce API or payment credentials.
4. Refresh the live catalogue and, if convenient, scan a **known real** SKU into a reference cart. Confirm checkout is locked. Disconnect networking: the window must close with a connection warning; reopening offline must refuse to load a stale POS. Reconnect and reopen to fresh sign-in. **No real sale, payment, stock change, Woo plugin installation or drawer kick is an authorized part of this test.** Use the separate hardware tester for non-selling printer paper checks.

If login, image loading or the pilot health check fails, stop and report the symptom rather than changing the server gate, disabling certificate checks, using the demo/practice till, or taking a payment. Staff administration, connection test and CSV export remain available from the separately installed web app as appropriate; this native QA build restricts them. Uninstalling this app does not affect the pilot's server ledger or the web app.

## Before any genuine online Windows checkout

This pilot is **not** a production POS or a successful live checkout test. The owner must separately approve a selling target and release, the service/Woo read-write gates and their backups, website/POS last-unit concurrency, Woo order creation/payment/stock and lost-response reconciliation, taxes/Wholesale, real printer/shift workflow, Windows install/upgrade/uninstall, code signing and a witnessed controlled sale. A later selling installer needs new reviewed code/identity and must make **every** checkout a synchronous server/Woo operation, failing closed when the online service or stock authority is unavailable. Do **not** switch this read-only installer into a selling build by changing the server configuration or repackaging the offline till.
