# Private wholesale defaults in the existing POS (branch 1.2.3)

**Code is installed on the read-only 1.2.3 pilot, but private-price access and all checkout remain blocked there; not approved for a live sale.** The editable workflow is for an isolated demo or a separately reviewed trading workspace with its own ledger. WooCommerce continues to own the one catalogue, retail price and stock. The POS ledger stores **only** optional private wholesale unit prices in GHS pesewas, indexed by exact Woo product/variation IDs and a snapshot of the product name, SKUs, option attributes and current website retail price. It does not store another product/stock balance or write wholesale prices to Woo metadata, public Store API, page, or online checkout.

- Owner: in **Inventory**, choose a product/size and select **Set private price**. Enter a positive all-in GHS unit amount (two decimals, including any applicable tax), then save. An existing value can be revised or removed. The edit is audited; a stale edit, including one made before a delete/recreate, gets a conflict instead of silently overwriting another change. Before saving, the server checks the Woo product/option and retail price against what the owner actually reviewed. This works in the isolated demo or in a future separate trading workspace, never on the live read-only catalogue pilot.
- Owner/manager: can view saved prices privately in **Inventory**. On **Wholesale**, a *matching* value prefills a newly added product/option. It is a suggestion, not a price change to Woo or an automatic sale: the authorised owner/manager must still review and explicitly approve **each** final quote, and Woo must return the exact all-in total. A tax line is shown on a resulting order or receipt only if Woo returned a positive tax amount. An edited quote is still valid for that one sale only.
- Cashier or unauthenticated visitor: cannot call the private price API. The ordinary `/api/catalog` still contains **retail prices only**. Cashiers remain Retail-only; separate cashier Wholesale authorisation is future work.
- Changed/deleted Woo identity, missing variation, changed name/SKU/attribute (including an attribute name with the same visible value), changed website retail price or stale/incomplete catalogue: saved value is marked **Needs review** and cannot prefill a quote. The owner must refresh and recheck the goods before saving it again. Many legacy Woo variations have no SKU; exact Woo IDs and named attributes are used to avoid unsafe guesses. Do not automatically transfer a default to a different product on name/SKU similarity.

Private price edits do not affect the pilot, create a Woo order, change website retail prices, adjust stock or turn on checkout. Forward-only SQLite migrations v6/v7 add the private table and identity/revision safeguards; preserve the **separate trading ledger** and its backups before installing a reviewed release. If a ledger already contains a v6 private default, v7 preserves it but marks it for re-review rather than silently trusting the earlier weaker identity snapshot. Existing historical Wholesale receipts and one-off negotiated prices remain intact. Do not copy private price rows from a demo or pilot ledger into trading.

Automated coverage: `tests/wholesale-prices.test.js` verifies roles, exact option matching, stale-identity rejection, concurrent edit conflicts, Woo-write isolation, and pilot locks; `tests/browser-wholesale-prices.mjs` exercises Inventory → Wholesale at counter/mobile widths and the private-price dialog's accessibility.
