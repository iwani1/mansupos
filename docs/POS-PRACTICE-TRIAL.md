# Windows POS practice trial — NOT FOR SALES

The owner reported that the earlier, separate **non-selling hardware check succeeded**. The individual Windows version, scanner/Enter, printer/cut and drawer results have not yet been recorded. This **new** app is a rehearsal of the offline POS ledger workflow on the one intended Windows computer. It is not the selling POS, is not connected to WooCommerce, Paystack, the read-only web pilot or a trading service, and cannot take or confirm a real payment. **No Woo plugin installation, live stock change, selling gate, public GitHub Release or real order is part of this step.**

This build uses the same protected SQLite checkout and durable event/queue algorithms as the draft desktop POS, with only built-in SAMPLE products and an **in-process fake service**. The fake connection switch does not use the internet. Its generated product snapshot uses a schema field named `source: woocommerce` solely because the shared ledger validates that shape; no Woo connection occurs. The practice app bundles neither the production HTTP client nor its live hostname, web renderer, updater, central server or WordPress plugin. Its renderer blocks network requests and has a `connect-src 'none'` CSP. Even its optional printer output says **NOT A RECEIPT** at the top and bottom.

## Obtain the explicitly requested test installer

Only a deliberately triggered `[practice-qa]` push on the working branch uploads a short-lived Actions artifact named `pos-practice-NOT-FOR-SALES-Windows-x64-…`. It contains one **unsigned Windows x64** installer, `SHA256.txt`, and this guide. A CI check opens the packaged Electron window, commits and reopens an encrypted sample event without printing, tests a fake retry/acknowledgement, and inspects the ASAR for only the permitted local files. This does **not** constitute a real-printer, installed-PC recovery or last-unit Woo test. The normal selling-POS CI job **discards** its unsigned installer. **No GitHub Release is made.** This repository is public; do not put staff/customer data or secrets in the artifact.

1. Download and extract the ZIP from the approved CI run's **Artifacts** section on the intended Windows x64 PC. Use only `Mansu-POS-PRACTICE-NOT-FOR-SALES-0.1.0-Windows-Setup.exe`, **not** an old POS installer or the previous Hardware Check installer.
2. Compare its hash in PowerShell with both `SHA256.txt` and the hash shown by the CI job:
   ```powershell
   Get-FileHash '.\Mansu-POS-PRACTICE-NOT-FOR-SALES-0.1.0-Windows-Setup.exe' -Algorithm SHA256
   ```
   If they differ, stop. The ZIP/artifact archive's SHA-256 is **not** the EXE's SHA-256.
3. It is unsigned. If Windows SmartScreen, antivirus or company policy blocks it, do **not** disable protection or proceed casually; stop and request a signed build instead. Install per-user, not as administrator. The installed shortcut and app name prominently include **NOT FOR SALES**; its icon is a separate orange **P**. Do not enter any real POS, Woo, Paystack or staff credentials.

## One-computer, no-selling walkthrough

Keep real products, money and customer information out of this test. A normal internet connection may remain on; the practice application has no network client. You can test with the physical keyboard-wedge scanner and printer if their driver is ready, but do not make a real payment or release goods.

1. Open **Mansu POS Practice - NOT FOR SALES**, then click **Open sample till**. No password or server address is requested. Confirm the red **PRACTICE ONLY / NOT A RECEIPT** banner and **Fake service: OFFLINE** badge. The catalogue contains only `QA-SCARF-01` (two sample units) and `QA-TEE-S` / `QA-TEE-L` (two units shared across the two size options). A real shop barcode must show “only SAMPLE codes” and add nothing.
2. Press **F2**, scan or type `QA-SCARF-01`, then Enter. Alternatively click **Add sample**. Choose a size if using the sample tee. Check the basket and sample quantity. Click **Review simulated checkout**. The tender is **illustrative only**. Do not handle cash; read and tick the explicit no-money/no-goods confirmation, then **Save sample event offline**. The resulting number begins `PRACTICE-`. The sample ledger, stock movement and pending event must be saved together. If checkout is blocked, do not use another POS to bypass it.
3. Click **Print NOT A RECEIPT** on the practice slip. Choose the tested Windows printer/driver and appropriate paper size (usually 80 mm if that is what the printer actually uses). Check readability, alignment, cut and the top and bottom warnings: **NOT A RECEIPT / NO PAYMENT ACCEPTED / NO GOODS RELEASED**. The app does not send a direct drawer-kick command; a printer driver's automatic drawer setting may still open a drawer. Disable auto-kick for this rehearsal if present, and report what happened. A printer dialog failure does not roll back the saved sample event.
4. In **Fake sync & recovery**, click **Attempt fake sync** while fake OFFLINE. The event should say `RETRY`, preserve its ID and remain pending. **Close the app fully and reopen it.** Click **Open sample till** again; find the same `PRACTICE-` number in Saved practice slips, same event ID and remaining sample balance. The fake connection deliberately resets to OFFLINE after relaunch.
5. Click **Fake CONNECTED**, then **Attempt fake sync**. The same event becomes `FAKE ACK`; pending count becomes zero. This is only a local acknowledgement. There is **no Woo order number, public stock change or shop/payment side effect**. Reprinting still says NOT A RECEIPT. If needed, **Make verified practice backup** stores a practice-only SQLite backup under `backups` in this app's own data folder; refresh never replenishes used sample units.

The separate data folder is `%APPDATA%\Mansu POS Practice - NOT FOR SALES\` (with `desktop-ledger.sqlite` and `backups\`), distinct from the selling POS's Windows folder. SQLite payloads are encrypted with Windows DPAPI; there is no plaintext fallback and another Windows user cannot simply open them. **Never copy a practice ledger into the selling POS, or copy real data into this app.** Uninstalling may leave the practice data folder; preserve a backup of the test evidence first, and never delete or rename the separate real POS data folder. Sample units are deliberately limited; if another trial is needed after they are exhausted, request a reviewed practice-only reset, not a new stock allocation from Woo.

Please report the Windows version/x64, scanner model and Enter suffix, what sample code appeared, printer driver/paper width/readability/cut, whether the drawer opened/stayed closed/is absent, and whether the **same event ID** survived restart and became `FAKE ACK`. Do not send customer data, actual product barcodes, card numbers or passwords.
