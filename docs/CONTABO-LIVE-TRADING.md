## Demo-free live build

Run `npm run build:live` in a dedicated live code directory. This builds the UI and excludes copied `public/demo` illustrations from `dist/` while keeping `favicon.svg` and the application. At runtime, a live/staging POS does not expose a demo sign-in API or serve `/demo/*` files, even if a normal build was accidentally copied. Non-demo ledgers never seed demo products, users, stock or example sales; on startup, old **unused sample-stock rows only** are removed from a non-demo ledger. Real users, orders and catalogue cache remain. A ledger containing demo-mode records or belonging to another mode is rejected rather than silently converted. Do **not** delete or restore over the separate demo, pilot or trading SQLite databases.

## Before a supervised first real sale

For **Woo Retail/Wholesale**, follow [LIVE-CASH-ROLLOUT.md](LIVE-CASH-ROLLOUT.md): inspect live order webhooks, Paystack/plugin triggers, emails and fulfilment; verify actual Woo tax/stock/status behavior and concurrent last-item control. **Preparing a Woo order itself is a live write.** No dummy order, gateway test payment, or globally disabled online checkout is part of that path. For the client's **new shared-Woo physical collection target**, follow [SHARED-WOO-STOCK.md](SHARED-WOO-STOCK.md); the legacy POS-only path must stay locked to avoid a second stock pool. Both paths need an off-host backup and isolated restore of the **new trading ledger**, verified drawer/printer and a written owner-approved genuine cash-sale plan. If any relevant side effect cannot be controlled, remain locked.

Only a reviewed administrator should later install the distinct service using a root-owned `0600` copy of `.env.live-trading.example` in `/etc/mansu-pos-live-trading/pos.env`, a separate `mansu-pos-trading` system user and data directory `/var/lib/mansu-pos-live-trading`. Never paste a key or temporary password into chat, Git, shell arguments or browser settings. Preflight fails until the new owner and Woo credentials are configured. With all write gates **false**, `/api/health` may be 200 while `/api/ready` is deliberately **503** (`Live write gates are disabled`); that is not a reason to enable writes early. Confirm localhost binding and that no demo records or assets are served. Back up the new ledger using the separate `mansu-pos-live-trading-backup.service` and test an isolated restore **before** enabling checkout.

After the owner signs off the pending/paid **Woo** order side effects, tax, shared stock safeguards and rollback/reconciliation plan, a separately reviewed Woo cutover may amend its specific write locks and use a dedicated restricted Woo key with necessary order access. For a Woo-backed first genuine sale, count cash and confirm that Woo order's total, stock and paid state before releasing goods. Wholesale additionally requires its own written decision and documented acceptance-plan reference, and stays locked until verified. The newly requested physical-source goods may only become shared-stock Woo products after an owner-reviewed identity crosswalk, draft/price/content/tax review and fresh stock cutover. A shop sale of those goods would use the separately approved **Woo-backed Wholesale** cash order, never a second `IS-...` POS-only stock deduction. Staff access must wait for observed real tax, last-unit safety, receipt, stock and backup acceptance. Nginx can be pointed from the pilot's upstream to the separate trading service **only after** an approved change review and `nginx -t`, without changing the other app's virtual host. Keep old orders and ledgers for reconciliation; never merge, reset or copy the demo/pilot database into trading.

**Emergency (only after a reviewed trading cutover):** Lock only the affected path and restart the trading service, preserving its ledger: `POS_ALLOW_LIVE_WRITES=false` blocks Woo Retail/Wholesale payment and remote cancellation (owner reconciles pending Woo orders directly); `POS_INSTORE_CASH_APPROVED=false` must stay off for the shared-Woo physical-source goods; review and reconcile any historical POS-only ledger separately, never merge it into Woo stock by a second deduction. Never roll back a ledger over newer records or disable live online Paystack to work around a POS problem.
